# v0.2.0 车况、电池详情与自适应刷新

用户已授权参考ha_ninebot扩展信息展示和自动刷新。范围限于车辆信息、电池详情、查询调度和必要配置；不包含控车、行程/轨迹归档、AI、专用面板、日历或自定义查询服务。

新增：普通预估/AI续航、ACC电门、独立接口的整车开机状态、电池存在、服务剩余天数；电池详情中的充电功率、通信备用电池电量及逐槽位电池电压/温度/循环支持与次数/评分。只接受明确范围内的值，缺失保持未知；评分不命名为SOH，循环次数须支持标记明确。原始车主资料、密钥、序列号及完整响应不进入状态或诊断。

直接Python实现，保持既有认证和HTTPS策略。电池路径依据用户此前App抓包确认：POST https://ebike.ninebot.com/v6/vehicle/battery-info，不使用研究报告中不同业务线的GET网关路由。实账号核对只保存允许列表中的数值、支持标记与字段存在性。

同一车辆的基础车况、独立电源查询和电池详情应有故障隔离；电池失败不让基础电量/GPS不可用。列表按小时更新。可禁用电池详情；可关闭位置展示。更新配置不能在保存刷新令牌时引起重载。已有实体ID保持稳定；电池槽位实体明确按位置编号而非假装电池永久身份。

自动模式按车调度：基础车况停车120秒、充电/有效ACC或开机状态30秒；电池详情停车600秒、开机120秒、充电60秒。使用新鲜的车端上报依据，过期/未知不提高频率；有短期状态变化窗口。固定模式保留30–3600秒设置，电池详情独立限频；失败退避并遵守429，不启动排队中的后续请求。新账号默认自动；旧配置保持固定模式，用户可主动启用自动。

在已约定的响应投影、异步客户端、协调器及HA配置/实体边界验证：未知/无效值，循环支持，电池槽位变化，基本与扩展查询故障隔离，按车到期/过期状态/退避，配置更新、卸载与持久令牌。发行前执行现有回归、类型/规范检查与两项代码审查；保留真实验证与模拟测试边界。
